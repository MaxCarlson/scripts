# Agent Continuity v2.1.3 Reliability Maintenance Backport

- **Base Ancestry**: Branched cleanly from `4ad834c3` (`v2.1.2`, `feature/llmd-claude-lifecycle-corrective-20261127`) onto `feature/llmd-v212-reliability-backports`, independent of the `v2.3.0`/`v2.4.0` feature lines and `MatchStatus.EXACT` restoration changes (`SCHEMA_VERSION = 3` preserved).
- **Version Metadata**: Updated `modules/agent_continuity/pyproject.toml`, `modules/agent_continuity/agent_continuity/__init__.py`, and `modules/scripts_help/scripts_help/registry/registry.py` to `2.1.3`.
- **Included Fixes**:
  1. **Concurrent first-use SQLite WAL & schema initialization** ([schema.py](../agent_continuity/schema.py)): retries `PRAGMA journal_mode = WAL;` and `BEGIN IMMEDIATE` DDL on transient `locked`/`busy` `OperationalError`s and uses `INSERT OR IGNORE` for `initialized_at`/`migrated_at` while keeping `SCHEMA_VERSION = 3`.
  2. **Atomic `prepare_start` / `begin_launch` mutation boundaries & spool dependency ordering** ([dispatcher.py](../agent_continuity/dispatcher.py), [events.py](../agent_continuity/events.py), [materializer.py](../agent_continuity/materializer.py)):
     - Kept `ExitStack` lock acquisition and `_emit_and_materialize` inside `_mutation_lock(self.home_dir)` in both `prepare_start` and `begin_launch`, preventing validation-to-commit races on empty-registry first launches.
     - Sorted `read_spool_events()` by `(observed_timestamp, _event_dependency_rank(event_type), event_id)` so equal-timestamp batches always replay in foreign-key dependency order (`environment.registered` -> `dispatcher.gui_registered` -> `dispatcher.slot_created` -> `dispatcher.launch_requested`).
     - Added reentrant `SQLiteMaterializer._writer_lock()` (`.index.sqlite.lock` via `ContextVar`) and `SQLiteMaterializer.publish_events()`, so `ContinuityService._emit_and_materialize()` appends all events of a multi-event batch and materializes them under the same writer exclusion as `sync_from_spools` RW re-scan and `rebuild_from_spools` (without nested non-reentrant locking or blocking cross-OS spool-only writes).
  3. **Metadata-attachment contention, lock-order safety, and unknown runtime observation boundary** ([dispatcher.py](../agent_continuity/dispatcher.py)):
     - `attach_session()` acquires `slot-{slot_id}.lock` before `dispatcher.lock` (matching launch/resume lock order to prevent AB-BA deadlocks).
     - `_observation_blocks_slot_wait` fails closed immediately on `ProcessLiveness.RUNNING`/`AMBIGUOUS`, `MatchStatus.AMBIGUOUS`, `AttachmentState.ATTACHED`, `identity_conflict`, or `evidence_conflict`.
     - `ProcessLiveness.UNKNOWN` (for example, Windows `psutil` partial access on protected system processes without any conflict, match, or attachment) is **not** treated as verified runtime inactivity; instead, it falls through to bounded `1.5s` exclusive `slot-{slot_id}.lock` acquisition, succeeding for short metadata contention and failing closed if a live launch/runtime process holds the lock.
  4. **Terminal-format test mock correction** ([dispatcher_cli.py](../agent_continuity/dispatcher_cli.py), [terminal_format_test.py](../tests/terminal_format_test.py)): routes CLI width lookups through `_get_terminal_size = shutil.get_terminal_size` and mocks `_get_terminal_size` with `os.terminal_size((..., 24))`.

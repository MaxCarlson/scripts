# Repository Validation Results

This directory stores tracked validation evidence generated by the repository-root `Invoke-Tests.ps1` dispatcher.

Evidence is grouped by validation target:

```text
docs/test-results/<target>/
├── LATEST.txt
├── LATEST_CONTEXT.md
├── LATEST_PROGRESS.diff
└── history/
    ├── YYYYMMDD-HHMMSS_<target>.txt
    ├── YYYYMMDD-HHMMSS_<target>_context.md
    └── YYYYMMDD-HHMMSS_<target>_progress.diff
```

## Relevance Rule

The three `LATEST.*` files are always authoritative:

- `LATEST.txt` — complete current validation output.
- `LATEST_CONTEXT.md` — branch, commit, validation highlights, working-tree state, and copies of configured project status/checklist files.
- `LATEST_PROGRESS.diff` — changes between the previous and current project-context snapshots.

A remote or hybrid implementation agent should read these files first. Files under `history/` are prior runs retained only for regression comparison and must not be treated as current evidence.

The dispatcher enforces bounded history by default:

- no more than three prior artifacts of each type per target,
- no prior artifact older than 14 days.

These limits can be overridden for a specific run:

```powershell
./Invoke-Tests.ps1 -MaxHistoryPerTarget 5 -MaxHistoryAgeDays 30
```

Legacy timestamped reports found directly under a target directory are migrated into `history/` on the next run.

## Context Sources

A validation target may declare `context_files` in `validation-targets.json`. Paths are relative to that target's working directory.

Example:

```json
"context_files": [
  "docs/plans/<active-plan>/STATUS.md",
  "docs/plans/<active-plan>/checklist.md"
]
```

The dispatcher copies the current contents into `LATEST_CONTEXT.md`; no duplicate manual progress report is required.

The repository-wide plan for this subsystem is:

```text
docs/plans/20260729-0900_validation-evidence-context-history/
```

## Normal Workflow

From the repository root:

```powershell
./Invoke-Tests.ps1
```

The script:

1. reads the validation target manifest,
2. selects the configured default target or targets,
3. resolves the repository Python environment,
4. installs each target's declared development dependencies unless `-SkipBootstrap` is used,
5. runs its language-native test commands,
6. runs its platform-specific validation scripts,
7. records complete stdout, stderr, environment context, exact commands, exit codes, and summaries,
8. archives the previous `LATEST.*` artifacts,
9. writes the current validation report and context snapshot,
10. generates a progress diff against the previous context snapshot,
11. removes history beyond the configured count or age limits.

Stage and push the changed `LATEST.*` files plus any history additions or removals made automatically. A remote implementation agent can then inspect both execution results and project progress without manual copy/paste.

## Target Selection

List configured targets:

```powershell
./Invoke-Tests.ps1 -ListTargets
```

Run selected targets:

```powershell
./Invoke-Tests.ps1 -Target rrbackup
```

Run all configured targets:

```powershell
./Invoke-Tests.ps1 -Target all
```

## Safety

Production access is disabled by default. Targets may expose explicit read-only checks through:

```powershell
./Invoke-Tests.ps1 -IncludeProductionReadOnly
```

The manifest must never enable destructive production operations as part of the default validation path.

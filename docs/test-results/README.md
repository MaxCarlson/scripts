# Repository Validation Results

This directory stores tracked validation evidence generated by the repository-root `Invoke-Tests.ps1` dispatcher.

Evidence is grouped by validation target:

```text
docs/test-results/<target>/
├── LATEST.txt
├── LATEST_CONTEXT.md
├── LATEST_PROGRESS.diff
└── history/
    ├── YYYYMMDD-HHMMSS_<target>.txt
    ├── YYYYMMDD-HHMMSS_<target>_context.md
    └── YYYYMMDD-HHMMSS_<target>_progress.diff
```

## Relevance Rule

The three `LATEST.*` files are always authoritative:

- `LATEST.txt` — complete current validation output.
- `LATEST_CONTEXT.md` — branch, commit, validation highlights, working-tree state, and copies of configured project status/checklist files.
- `LATEST_PROGRESS.diff` — changes between the previous and current project-context snapshots.

A remote or hybrid implementation agent should read these files first. Files under `history/` are prior runs retained only for regression comparison and must not be treated as current evidence.

The dispatcher enforces bounded history by default:

- no more than three prior artifacts of each type per target,
- no prior artifact older than 14 days.

These limits can be overridden for a specific run:

```powershell
./Invoke-Tests.ps1 -MaxHistoryPerTarget 5 -MaxHistoryAgeDays 30
```

Legacy timestamped reports found directly under a target directory are migrated into `history/` on the next run.

## Context Sources

A validation target may declare `context_files` in `validation-targets.json`. Paths are relative to that target's working directory.

Example:

```json
"context_files": [
  "docs/plans/<active-plan>/STATUS.md",
  "docs/plans/<active-plan>/checklist.md"
]
```

The dispatcher copies the current contents into `LATEST_CONTEXT.md`; no duplicate manual progress report is required.

The repository-wide plan for this subsystem is:

```text
docs/plans/20260729-0900_validation-evidence-context-history/
```

## Normal Workflow

From the repository root:

```powershell
./Invoke-Tests.ps1
```

The script:

1. reads the validation target manifest,
2. selects the configured default target or targets,
3. resolves the repository Python environment,
4. installs each target's declared development dependencies unless `-SkipBootstrap` is used,
5. runs its language-native test commands,
6. runs its platform-specific validation scripts,
7. records complete stdout, stderr, environment context, exact commands, exit codes, and summaries,
8. archives the previous `LATEST.*` artifacts,
9. writes the current validation report and context snapshot,
10. generates a progress diff against the previous context snapshot,
11. removes history beyond the configured count or age limits.

Stage and push the changed `LATEST.*` files plus any history additions or removals made automatically. A remote implementation agent can then inspect both execution results and project progress without manual copy/paste.

## Target Selection

List configured targets:

```powershell
./Invoke-Tests.ps1 -ListTargets
```

Run selected targets:

```powershell
./Invoke-Tests.ps1 -Target rrbackup
```

Run all configured targets:

```powershell
./Invoke-Tests.ps1 -Target all
```

## Selective Pytest (Existing Environment)

For a focused regression check, pass an explicit consumer target and one or more selectors. The dispatcher supports pytest node IDs, files/directories, dotted test modules, and the `-AffectedTarget` alias for consumer context:

```powershell
./Invoke-Tests.ps1 -Selective -AffectedTarget compresser -PytestNodeId 'tests/test_pipeline.py::test_retries_after_timeout'
./Invoke-Tests.ps1 -Selective -Target scheduler -PytestFile tests/test_history.py -PytestModule tests.test_cli.test_help
```

Use `-PythonExecutable` to select a specific already-existing interpreter. Selective mode invokes only the configured pytest command for the selected items. It does not enter normal target bootstrap, install/uninstall packages, rebuild an environment, run lint/compile/CLI or PowerShell stages, mutate `LATEST.*` or history, or call the development-ledger recorder. It fails closed when the configured import does not resolve to the consumer checkout or a retired source copy is present. If editable distribution metadata points elsewhere while the live import resolves to the selected checkout, the receipt records that stale editable source as a warning rather than mutating the environment. The target must declare a `selective_validation` contract in `validation-targets.json`.

Each run writes an immutable JSON receipt to `docs/test-results/selective/runs/<execution-id>.json` and uses a UUID-scoped pytest temporary directory under the target's `.pytest_tmp_root/`. Pass `-TemporaryRoot <path>` to put temporary files outside the repository. Receipts record exact selectors and commands, interpreter and installed-distribution identities, imports/origins from both preflight and the pytest process, source/dependency hashes, Git revision, duration and exit status. Passing evidence is never reused automatically. Add `-ReuseEvidence` to opt in; reuse is disabled when editable dependency identity cannot be content-verified, and a successful run is marked `invalidated` if relevant inputs change while pytest runs. Failed, blocked, and invalidated attempts are not reused.

The receipt's `qualification_scope` is `source-level` when the contract points imports at the consumer checkout and `installed-distribution` only when every declared import is expected in site-packages. Source-level tests do not qualify a wheel or replace the shared-package artifact validation process.

This is the Scripts-side interface only. Toolkit-native consumers can adopt the command contract independently; this change does not modify Toolkit diagnostics or its test workflows. Selective validation currently supports only manifest targets with `selective_validation` metadata and pytest tests. Editable distributions outside this repository, incomplete installed-distribution metadata, or external symlinks make evidence ineligible for reuse; they do not trigger dependency installation. A source change detected during pytest marks the run `invalidated` even when pytest returned success.

Consumer-facing form for Agent-Environment `test-verify`:

```powershell
./Invoke-Tests.ps1 -Selective -AffectedTarget <manifest-target> `
  -PytestNodeId '<target-relative-test-file>::<test-name>' `
  -PythonExecutable '<existing-python.exe>' `
  -TemporaryRoot '<external-temp-directory>'
```

Repeat `-PytestNodeId`, `-PytestFile`, or `-PytestModule` to select multiple items. The default interpreter resolver is used when `-PythonExecutable` is omitted. Evidence reuse requires explicit `-ReuseEvidence`. Selective mode never performs setup as a fallback; choose an existing interpreter whose dependencies and import origins already satisfy the target contract.

## Safety

Production access is disabled by default. Targets may expose explicit read-only checks through:

```powershell
./Invoke-Tests.ps1 -IncludeProductionReadOnly
```

The manifest must never enable destructive production operations as part of the default validation path.

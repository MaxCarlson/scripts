# Scripts Repository Standards

This file contains standards specific to the `scripts/` repository.

Reusable Python policy lives in `docs/agent/PYTHON_REPO_STANDARDS.md`.

## Setup / Reinstall Semantics

Modules under `modules/<name>/` use `pyproject.toml` `[project]` version, optionally mirrored in `<name>/__init__.py` as `__version__`.

Repository setup behavior:

| Changed | Version level | Setup action |
|---|---|---|
| Bug fix, refactor, docs, or tests only | PATCH | No reinstall; editable install picks up source changes. |
| Backward-compatible feature or non-entry-point `pyproject.toml` deps/metadata change | MINOR | `pip install -e .`; existing wrappers stay valid. |
| `[project.scripts]` or `[project.entry-points]` added, removed, or renamed | MAJOR | Full uninstall/reinstall so wrappers are regenerated. |

Decision rule:

```python
if source_major > installed_major:
    pip_uninstall_then_install(module_dir)
elif source_minor > installed_minor:
    pip_install_e(module_dir)
else:
    pass
```

## Module Dependency Ordering

When adding a new module that depends on core modules, ensure it installs after its dependencies.

Core order:

1. `standard_ui` — no dependencies
2. `cross_platform` — no dependencies
3. `python_setup` — depends on `cross_platform`
4. `scripts_setup` — no dependencies

All other modules should declare dependencies in `pyproject.toml`; dependency resolution handles ordering.

## Help Registry

After adding a new pyscript or module-with-CLI, add an entry to:

```text
modules/scripts_help/scripts_help/registry/registry.py
```

If updating an existing entry description, update its registry version to match the live version so staleness checks stay quiet.

## Module Test Temp Roots

Module tests must keep generated temp directories inside the owning module directory unless the user explicitly asks otherwise.

Preferred pattern:

```text
modules/<module>/.pytest_tmp_root/<module>-temp-<pid>/
```

Do not create repo-root scratch folders such as `.tmp-<module>-run/`, `codex_tmp_test/`, or `pytest-of-<user>/` from module tests.

## Cross-Platform Utilities

Use `SystemUtils` from `cross_platform` for OS detection when working in modules that depend on it. Avoid direct `sys.platform == "win32"` checks in module code when a project utility exists.

## Entry Point / `.cmd` Conventions

Console scripts are defined in `[project.scripts]` in `pyproject.toml`. The `.cmd` wrapper in `.venv/Scripts/` is generated by `pip install`.

- Never hardcode `.cmd` paths.
- Use `$PATH` / the active virtual environment.
- When adding, renaming, or removing a script, bump MAJOR and document the change.

## ytaedl Partial / Temp Conventions

When a module manages per-operation working directories:

- Use `_partial/<hash12>/` where `hash12` is the first 12 hex chars of a sha256 key.
- Write `meta.json` before starting work.
- Delete the working dir on success.
- Keep it on failure for resume.
- Write an empty `.ignore` in media/library subdirectories to prevent indexing in-progress files.
- Track partial-format version in `_partial/.version`.

## Termdash-First UI Reuse

If a terminal widget is reusable, build it inside `modules/termdash` and consume it from callers instead of duplicating ad hoc UI code.

Keep color/status conventions consistent across dashboards, logs, progress displays, and hotkeys.
